# 刹车卡钳批次追溯系统

面向汽车零部件厂的批次谱系、双向追溯与召回模拟系统。全栈 TypeScript：后端 Node + Express + SQLite，前端 React + Vite。

客户投诉场景（`CC-2025-0917`）：一批刹车卡钳装车后制动异响，需在分钟级回答两个问题 —— **这批用了哪几炉炉料（ADC12 铝锭）**、**同炉料还流到了哪些成品和客户**。传统靠 MES 截图 + 纸质流转卡需要约 3 天。

## 快速开始

```bash
npm install
npm run setup     # = seed + ingest + verify，一条命令跑完
# 或分步：
npm run seed      # 生成一个月的模拟生产数据到 data/exports + 真值 data/truth/truth.json
npm run ingest    # 三系统数据接入、归一化、建谱系、标记可疑批次
npm run verify    # 与真值逐批对照 + 数量守恒校验（有偏差时退出码非 0）

npm run dev       # 后端 :5174 + 前端 :5173
# 或
npm run build && npm start   # 单进程托管，访问 http://localhost:5174
```

## 功能

| 模块 | 说明 |
| --- | --- |
| 数据接入 | MES 工序明细（拍平 CSV）、WMS 出入库、QMS 检验记录、发货单。去重、编码映射、时区/格式归一、批次引用纠错 |
| 批次谱系 | 原料 → 熔炼铸造 → 机加 → 装配 → 成品的有向图，含拆批 / 合批 / 返工 / 报废 |
| 正向追溯 | 原料批次 → 全部下游成品 → 发货单 → 客户，按投入占比折算受影响当量 |
| 反向追溯 | 成品序列号 → 全部原料批次（含权重）、供应商、工序设备/操作工/工艺参数 |
| 质量与可疑批次 | IQC/IPQC/FQC 不合格自动标记本批与全部下游；实测值超限但录为 PASS 的记录自动改判 |
| 召回模拟 | 需召回件数、涉及发货单（A/B/C 分级）、可拦截库存、成本拆解（物流/返修/报废） |
| 8D 报告 | 组装 D1–D8 + 原料/工艺/守恒附件，导出 Word (.docx) 与 Markdown |

## 业务难点与实现

### 1. 谱系建模：数量按比例归因

一次工序的多投入、多产出（拆批）不只是"有边"，还要能回答"这一件成品里有多少来自那一炉"。

- **BLEND（熔炼/机加/成品）**：按投入数量比例分摊。熔炼是 kg→件，按 2.45 kg/件 折算并单独记报废。
- **ASSEMBLY（装配）**：本体、密封件、活塞是三条并行物料通道，`group_key` 分开归一。跨组取**最大值**而非相加 —— 一炉铝不可能既经本体又经密封件影响同一件成品两次。
- 边权 `weight` = 组内投入占比 × 产出占比，报废按投入比例摊薄。

### 2. 三系统编码与时间对齐

| 系统 | 批次编码 | 物料编码 | 时间 |
| --- | --- | --- | --- |
| MES | `20250916009`（日期+班次流水） | `CAL-FIN` | 本地时间，无时区，少量 `YYYY/MM/DD` |
| WMS | `WH-20250916-121`（库位标签） | `10001007`（10 位） | UTC ISO |
| QMS | `Q-20250916-04-009` / `IQ-H2509014` | `A07`（短码） | `DD/MM/YYYY HH:mm` |

对齐策略（按可信度降序）：

1. WMS 收货/入库单携带 `prod_lot` → 精确对齐
2. 缺失 `prod_lot` 时按 **物料 + 数量 + 日期邻近** 反查唯一批次
3. QMS 批码按规则还原为工厂批次号
4. MES 投入引用经形近字符 / 相邻转置 / 尾部多余字符 / 编辑距离纠正

无法唯一确定的记录**不强行匹配**，而是留在问题清单里标红，避免把追溯结果做"假"。

### 3. 模拟数据与真值对照

`npm run seed` 生成 2025-09 整月生产（26 个工作日），同时留下两份产物：

- `data/exports/` —— 按三系统各自格式导出的"脏"数据
- `data/truth/truth.json` —— 真实谱系，用于逐批对照

注入的数据问题（19 处）：

| 类型 | 数量 | 处理方式 |
| --- | --- | --- |
| MES 重复导出行 | 3 | 行级去重（展开后 8 行） |
| 时间格式 `YYYY/MM/DD` | 5 | 格式归一 |
| WMS 缺 `prod_lot` | 4 | 物料+数量+日期反查 |
| MES 输入批次录错 | 3 | 编辑距离/形近字符纠正 |
| QMS 实测超限但录为 PASS | 2 | 按实测改判 FAIL |
| WMS 物料编码错位 | 1 | 按批次反推 |
| MES 主产出与明细不符 | 1 | 以明细为准并告警 |

### 4. 校验口径（`npm run validate`）

| 检查 | 当前结果 |
| --- | --- |
| 谱系边 precision / recall | 100% / 100%（真值 477 条边，缺失 0，虚构 0） |
| 逐工序数量守恒 | 4 个工段全部平衡（偏差 0.000%） |
| 批次级产出量 | 264 / 264 一致 |
| 原料 → 序列号端到端 | 精确率 100%，召回率 100% |
| 投诉炉号逐批归因 | 6 个成品批偏差全部 ≤ 2% |
| 数据问题识别 | 注入 19 处，识别 11 条 + 自动纠正 9 条 |

归因对照使用**独立实现**（在 truth.json 上按量重算），不复用生产代码，避免自证。

## 目录结构

```
shared/          前后端共享类型、物料主数据、时间/编码归一规则
server/src/
  sim/           生产模拟器（可复现 PRNG）+ 真值导出
  ingest/        CSV/JSON 解析、去重、编码映射、时间对齐、谱系构建、落库
  trace/         图加载、正向/反向传播、召回模拟、真值校验
  quality/       不合格传播与可疑批次标记
  reports/       8D 报告（docx + markdown）
  api/           REST 接口
client/src/      8 个页面：概览 / 数据接入 / 谱系图 / 正向 / 反向 / 质量 / 召回 / 8D
data/            exports（脏数据）、truth（真值）、trace.db
```

## API 摘要

```
POST /api/ingest/run                 重新接入并归一化
GET  /api/ingest/status              接入统计、问题清单、映射表
GET  /api/genealogy/:lot             以某批次为中心的谱系子图
POST /api/trace/forward   {lot}      正向追溯
POST /api/trace/backward  {serial|lot} 反向追溯
POST /api/recall/simulate {lot|serial}  召回模拟
GET  /api/quality/failures           不合格记录 + 波及估算
GET  /api/validate                   与真值对照的完整校验报告
POST /api/reports/8d                 生成 8D（返回 markdown + 下载链接）
GET  /api/reports/8d/download        下载 .docx
```

## 已知取舍

- 卡钳按行业主流选 ADC12 铝合金压铸（铁为杂质元素，故 IQC 卡含铁量）；若产线为铸铁件，只需改 `shared/materials.ts` 的主数据与模拟器参数。
- 模拟数据为单厂单月、单班制，5 家客户、7 张发货单；真实场景需扩展到多工厂与历史归档。
- 召回默认采用**保守口径**（受影响成品批次的已发全部召回，安全件行业惯例），同时给出按投入贡献折算的精确口径用于成本预估与对比。
- 归属比例低于 0.2% 的成品批视为数值噪声，在界面折叠展示，但仍计入端到端校验。
- 校准类错误（如录错但无法唯一纠正）保留为 ERROR 并阻断该工序的谱系边，宁可缺失也不虚构。
- 召回成本模型为线性估算（单件 268 元、运费 42、返修 85、报废残值 15%），可按财务口径替换。
